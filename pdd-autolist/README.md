# 拼多多自动上架

客户：五金紧固件，两个拼多多店铺。资料是店透视从同行导出的 zip（表格 + 主图 + SKU 图 + 详情图），标题和图片照原样上。

## 文件

| 文件 | 干什么 |
|---|---|
| `loader.py` | 读店透视导出的资料，zip 会自动解压；SKU 图按文件名对到 SKU |
| `main.py` → `dist/拼多多上架.exe` | 检查资料 / 试填一个（不提交）/ 开始上架；多店铺、每天上限、断点续传、结果表、失败截图。双击 exe 打开面板，`python main.py 菜单` 是老的黑窗口菜单 |
| `gui.py` | 操作面板（tkinter）：选店铺、改常用设置、三个按钮、停止、进度和运行记录；在后台线程里调 main.py |
| `publish.py` | 在商家后台点页面发一个商品，提交前逐行核对价格库存和预览图 |
| `python main.py 远程试填 [资料文件夹]` | 开发用：通过隧道（browser.py 的 open_remote_edge）连客户开着的 Edge 试填第一个商品，不提交；图片以内容传过去 |
| `browser.py` | 像普通人一样启动 Edge 再连上去（Playwright 直接启动会被拼多多弹滑块）；Edge 还开着就直接连回去 |
| `capture.py` → `dist/页面采集.exe` | 远程时录发布页：每一步存网页、截图、按钮输入框列表和提交请求 |
| `test_offline.py` | 用 `采集结果/` 里的网页快照检查 publish.py 的定位还找不找得到（拼多多改版后先跑这个） |
| `设置.json` | 店铺、每天上限、间隔、价格来源/公式、标题长度、类目、默认属性 |
| `交付/拼多多上架/` | 给客户的文件夹：exe + 设置 + 使用说明 + 待上架（不进 git） |

## 发布流程（从采集结果看出来的）

1. `/goods/category`：传主图 → 填标题 → 拼多多按标题推荐类目，点一个 → 下一步
2. `/goods/goods_add`：品牌（无品牌/无注册商标）→ 详情图 → 规格类型「型号」+ 一个个输规格值 → 价格库存表（批量设置库存，每行填拼单价/单买价，预览图格子里直接传图）→ 商品参考价 = 最高单买价 + 1 → 提交并上架
3. 成功后跳到 `/goods/goods_add/success?goods_id=...`

提交请求带 `crawlerInfo` / `validate_message` 反爬签名，不能绕过页面直接调接口。

## 第 2 次远程测试清单

还没在真页面上点过的地方，按风险从高到低：

1. **规格类型选「型号」**：下拉选项的结构没录到，可能点不中
2. **输规格值**：填一个按回车后会不会自动多出一个空框
3. **66 行价格表**：表格是虚拟滚动的，滚动找行能不能找全；每行传预览图会不会卡
4. **批量设置**：填了库存点「批量设置」能不能一次填满
5. **提交后的确认弹窗**：价格预警之类的弹窗按钮文字
6. **推荐类目**：不同螺丝商品推荐的第一个类目对不对

步骤：
1. 交付文件夹放进客户的「拼多多上架」文件夹（和 `浏览器数据` 放一起，登录状态能接着用）
2. 改 `设置.json` 店铺名；商品 zip 放进 `待上架`
3. 菜单 1 检查资料 → 菜单 2 试填一个，在浏览器里核对 → 有问题看黑窗口和 `失败截图`，改代码重新打包
4. 试填没问题后菜单 3 正式上 1 个，客户确认后再放开批量
